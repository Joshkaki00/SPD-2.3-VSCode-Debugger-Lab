## Notes for Exercise 7

I ran the code first to confirm the bug. It printed only "fantastic" instead of the full sentence. I put a breakpoint on the base case to see what it looked like before stepping through the rest. I put it on line 4, which is a comment, so VS Code moved it to line 3 instead. I also stepped through the recursive case with the Variables panel open using continue for the base case, then step into for the rest to see what the sentence was being replaced with. The first bug I ran into was line 10. After the line ran, remainder_of_sentence was empty. I expected it to hold the rest of the sentence after the first "okay". The line was slicing start_str from index 4, and "okay" only has indexes 0 to 3, so the result was always an empty string. That empty string was passed to the next call, which hit the base case right away and returned, so everything after "fantastic" disappeared. I figured out the slice needed to be applied to sentence, not start_str, and kept the same length so it skips past the match. I changed it to use sentence. The second bug I ran into was line 13 in the else branch. The recursive call was passing start_str with the first character removed, which is "kay", instead of the rest of the sentence, so it replaced the sentence with ",kay" instead so the file printed "fantastic,kay" instead. It was the same mistake as the first bug, slicing the start word instead of the sentence. I changed it to pass sentence with the first character removed. I reran the code and got "fantastic, I guess programming is fantastic." as expected. Both bugs were the same mistake which was slicing start_str where I needed sentence. Comparing what the variables should have held with what they actually held in the Variables panel is how I found both.
